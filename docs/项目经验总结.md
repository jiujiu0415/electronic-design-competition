## 1. SPI 配置铁律

**来源**：01-f103-ad9833-signal-gen — Bug #1

**问题**：CubeMX 里 CPHA 选错了边沿，波形出不来。

**铁律**：

```
配任何芯片的 SPI 之前：
  ① 找到数据手册里的时序图
  ② 画出：SCLK 空闲 = 高还是低？
  ③ 画出：数据在哪个边沿被采样？
  ④ 对照 CubeMX 的 CPOL/CPHA 去匹配，不要猜
  
口诀:
  CPOL = 空闲电平 (Low=0, High=1)
  CPHA = 第几个边沿采样 (1 Edge=第1个, 2 Edge=第2个)
```

**已踩实例**：

| 芯片 | CPOL | CPHA | Mode |
|------|------|------|------|
| AD9833 | High | 1 Edge | Mode 2 |
| *(后续芯片按此格式补充)* | | | |

## 2. 寄存器位操作铁律

**来源**：01-f103-ad9833-signal-gen — Bug #2

**问题**：释放 RESET 位时写了全新的控制字，把波形配置位覆盖成 0。但正弦波恰好波形位全是 0，测试通过了，三角和方波失败。

**铁律**：

```c
// ❌ 错误：写新值覆盖整个寄存器
AD9833_WriteRegister(BIT_B28);

// ✅ 正确：在原值基础上只改你要动的那一位
AD9833_WriteRegister(wave_ctrl & ~BIT_RESET);
```

**关键**：
- 改一个 bit 用 `(old & ~BIT) | new_val`，不要写"看起来差不多"的全新值
- **测试所有状态组合**，一种 pass 不代表全对
- 检查哪些位恰好是 0 才让你的 bug 逃过了测试

## 3. ARM MCU 烧录调试排查链

**来源**：MSPM0G3507 调通经历

**问题**：SW Device 能检测到芯片 ID，但 Flash 烧写失败。

**核心认知**：**SWD 能检测 ≠ 能烧录** — 读 IDCODE 只需低速通信，Flash 写入需要稳定时序 + 正确解锁序列。

**排查顺序（从易到难，从软到硬）**：

| 优先级 | 操作 | 解决什么问题 |
|--------|------|-------------|
| ① | 降 SWD 时钟到 100~500kHz | 走线长、容性负载大导致高速数据出错 |
| ② | 改 Reset 方式为 SYSRESETREQ | Flash 控制器需要正确的复位状态 |
| ③ | 确认 RAM for Algorithm (Start+Size) | 调试器用芯片 RAM 跑 Flash 算法，没填/太小就失败 |
| ④ | 接上 nRST 线 + Hardware Reset | 硬件复位能绕过部分软件保护机制 |
| ⑤ | Mass Erase / Uniflash 整片擦除 | 芯片 CCFG 写保护位阻止了 Flash 写入 |

## 4. CubeMX/CubeIDE 配置陷阱

**来源**：03-g474-dual-ad9833-fft 配置过程

### 4.1 HSE vs HSI

- NUCLEO 板：HSE 时钟来自 ST-LINK MCO（8MHz），选 **BYPASS Clock Source**
- 裸芯片无晶振：直接用 **HSI**（16MHz 内部 RC），PLL Source 别选 HSE
- **先看板子上有没有晶振再决定**

### 4.2 Scan Conversion Mode 灰掉

- STM32G4: 把 Number Of Conversion 设 ≥2 → 自动启用扫描
- 灰着不用管，CubeMX 会自动处理

### 4.3 DMA 在 ADC 自己的标签页里加

- **不是** System Core → DMA → Add
- **是** ADC1 → DMA Settings 标签 → Add → 选 ADC1
- CubeIDE 里 DMA 和外设是绑定的

### 4.4 CubeMX SPI 模式选择

**来源**：04-g474-lcr-sweep-fft 配置过程

CubeMX 的 SPI 有三种模式：
| 模式 | 占用引脚 | 适用场景 |
|------|----------|----------|
| Full-Duplex Master | SCK+MISO+MOSI | 需要双向通信 |
| **Transmit Only Master** | SCK+MOSI | **只写不读**（如 AD9833 DDS、LCD 屏幕） |
| Receive Only Master | SCK+MISO | 只读不写 |

- AD9833 只有 SDATA 输入线，没有 MISO → 用 **Transmit Only Master**
- TFT LCD 画图只需写命令+数据，不用读回 → 用 **Transmit Only Master**
- 好处：省一个引脚（MISO），简化接线
- 代价：无法读回屏幕 ID/状态寄存器（通常不需要）

### 4.5 CubeMX 引脚手动重新分配

**来源**：04-g474-lcr-sweep-fft 配置过程

**问题**：CubeMX 自动给 SPI2_SCK 分配了 PF1，而不是预期的 PB13。因为默认芯片模板可能给某些引脚预设了功能（如 NUCLEO 板的用户按钮）。

**解决**：
1. Pinout 视图里找到被自动分配的引脚 → 右键 → **Reset Pin** 清除
2. 找到目标引脚 → 右键 → 选对应外设信号
3. 如果目标引脚上有残留标记（黄色/橙色），先清掉再分配

**要点**：裸芯片/自定义板子 ≠ NUCLEO 板，CubeMX 不知道你的实际硬件，引脚分配要靠手动确认。

### 4.6 STM32G4 ADC 单端/差分模式

**来源**：04-g474-lcr-sweep-fft 配置过程

STM32G4 的 ADC 输入引脚必须先设 **模式** 才能用来采集：
- **INx Single-ended**：普通单端采集，对 GND 测电压 ← 99% 情况用这个
- **INx Differential**：差分模式，测两个引脚之间的电压差
- 默认是 **Disabled**，不设的话 Rank 的 Channel 下拉列表里找不到这个通道

**口诀**：G4 ADC 配通道 → 先选 Single-ended，再配 Rank，不能跳过。

### 4.8 CubeMX 界面选项名不要凭记忆写

**来源**：04-g474-lcr-sweep-fft 配置过程

CubeMX 不同 MCU 系列的选项名称可能不同。比如 STM32G4 的 ADC End Of Conversion 实际选项是 `End of sequence of conversion`，而不是凭 F1/H7 记忆写的名字。

**铁律**：写配置指南时，选项名必须对照实际 CubeMX 界面/截图，不凭记忆。CPU 系列不同、CubeMX 版本不同，同一个功能的标签名都可能变。

### 4.9 【总则】每次错误必须当时存档

**来源**：04-g474-lcr-sweep-fft 配置过程

用户明确要求："你犯的任何错、任何经验都在总结保存下来"。光在对话框里说"下次注意"不算数。每条经验必须同时存档到：
1. `docs/项目经验总结.md` — 项目级经验
2. `memory/` 目录 + `MEMORY.md` 索引 — 跨 session 记忆

说出来的瞬间就要写进去，不等用户提醒。

```
VCO = PLL输入 × PLLN    (96~344 MHz)
SYSCLK = VCO / PLLR     (max 170 MHz)

例: HSI 16MHz / 4 × 85 = 340MHz → /2 = 170MHz ✓
```

## 5. 项目管理习惯

### 5.1 截图备份

- CubeMX/CubeIDE 每次配完 `.ioc`，截图保存：
  - Clock Configuration 页面
  - Pinout 视图
  - 每个外设的 Param Settings
- 电赛现场重配时能省一半时间

### 5.2 目录规范

```
projects/{序号}-{mcu}-{功能描述}/

每个项目至少包含:
  README.md         — 目标 + 硬件 + 引脚表 + 状态
  驱动代码           — 头文件 + 实现
  接线文档           — 杜邦线怎么连
  配置指南           — CubeMX/CubeIDE 怎么配
```

### 5.3 Git 提交粒度

- 一个阶段完成 → 一次 commit
- Commit message 用中文，描述"做了什么"而不是"改了什么文件"
- 例子：`新增: AD9833 双模块驱动适配 STM32G474` 而不是 `修改 ad9833.c`

## 6. 核心方法论

```
数据手册是第一手资料，IDE/教程/blog 都是二手
     │
     ├── 时序图 → 确定通信参数 (CPOL/CPHA/速率)
     ├── 寄存器表 → 搞清楚每一位含义 → 写 #define
     ├── 操作流程 → 先复位→配参数→释放复位→正常运行
     └── 电气特性 → 电压/电流/时序约束
     
每一点都要在代码里有对应体现。
找不到对应关系的，就是潜在 bug。
```

**一句话**：对照手册写代码，不要凭感觉。手册上的约束代码里没体现 → bug。
