## 3. Page 0 — 波形页详细配置

> ⚠️ **重要**：组件拖入画布后，软件自动分配数字名（`1`, `2`, `3`...）。
> 必须在右侧属性面板把 **`objname`** 改为下表中指定的名称（如 `n0`, `s0`）。
> `objname` 是 MCU 指令中引用的组件标识符，**不能错**。

### 3.0 页面背景

点击画布空白区域 → 属性面板：

| 属性 | 值 | 说明 |
|------|-----|------|
| `bco` (背景色) | **`65535` (白色)** | 白底，比赛现场无反光问题，拍照清晰 |

### 3.1 顶部参数栏

参数值用**数字组件**，标签用**文本组件**。

#### n0 — Vpp (mV)

工具箱 → 拖入「数字」组件 → 属性：

| 属性 | 值 | 说明 |
|------|-----|------|
| `objname` | **n0** | **必须严格匹配代码** |
| `x` | 5 | 距左 |
| `y` | 3 | 距顶 |
| `w` | 130 | 宽度 |
| `h` | 40 | 高度 |
| `val` | 0.0 | 初值，程序运行后自动更新 |
| `pco` | `0` (黑) | 数字颜色（白底黑字） |
| `bco` | `65535` (白) | 与页面背景同色 |
| `font` | 24~28 | 字号 |
| `isImg` | 0 | 不用图片 |
| `format` | **`%0.1f`** | 1位小数, 精度 ±0.1mV |

> MCU 发送：`n0.val=150.2` → 屏幕显示 **150.2** mV

#### n1 — Vrms (mV)

拖入「数字」组件 → 属性：

| 属性 | 值 |

| `objname` | **n1** |
| `x` | 185 |
| `y` | 3 |
| `w` | 140 |
| `h` | 40 |
| `val` | 0.0 |
| `format` | **`%0.1f`** |

> MCU 发送：`n1.val=52.8` → 屏幕显示 **52.8** mV

#### n2 — f₁ (Hz)

| 属性 | 值 |
|------|-----|
| `objname` | **n2** |

| `format` | **`%0.1f`** |

> f₁ 经 500Hz 吸附后为 N×500.0。MCU 发送：`n2.val=10500.0`

#### 文本标签（参数说明）

> n3 (基波 Vpeak) 已移除 — 赛题 1-(2) 只要求 Vpp/Vrms/f₁。

在每组数字旁边放文本组件作为标签。不设 id（不需要 MCU 更新），直接在属性里写死文字：

| 标签 | 文字 | 位置 | 字号 |

### 3.2 波形控件 s0

工具箱 → 拖入「波形」组件 → 属性：

| 属性 | 值 | **必须严格** |
|------|-----|-------------|
| `objname` | **s0** | ✅ 代码用的 s0 |
| `x` | 40 | 左右居中 |
| `y` | 50 | 参数栏下方 |
| `w` | **700** | ✅ 匹配 `SCOPE_DISP_WAVE_WIDTH` |
| `h` | **280** | ✅ 匹配 `SCOPE_DISP_WAVE_HEIGHT` |
| `dis` | 1 | 单通道 |
| `dir` | 0 | 水平方向（波形从左→右滚动） |
| `grid` | 1 | 显示网格 |
| `gdc` | `50712` (浅灰) | 网格线，白底用浅灰 |
| `bco` | **`65535` (白)** | 波形区背景，与页面一致 |
| `pco1` | `63488` (红) 或 `31` (蓝) | ch0 波形颜色，白底上深色线清晰 |
| `chs` | 2 | 通道线宽 2px |

> **pco1 / pco2 / pco3 / pco4** 分别对应 ch0~ch3 的波形颜色。
>
> 白底配色建议：线用深色（红 `63488`、蓝 `31`、深绿 `1024`、黑 `0`）。
>
> 常用颜色值：`65535`=白, `0`=黑, `63488`=红, `2016`=绿, `31`=蓝, `65504`=黄, `1375`=橙, `1024`=深绿。

## 6. 编译与下载到屏幕

### 6.1 编译

工具栏 → **编译**（或 F7）

输出文件在工程目录的 `output/` 下：
- `scope_analyzer.tft` — 屏幕固件文件

编译信息窗会显示：
```
编译成功！
Flash占用: xxx KB
```

### 6.2 下载方式

#### 方式 A：串口下载（推荐，调试期间）

```
所需硬件: USB转TTL 模块 (TX/RX/GND)

连接:
  USB-TTL TX  → 屏幕 RX
  USB-TTL RX  → 屏幕 TX
  USB-TTL GND → 屏幕 GND
  屏幕 VCC    → 5V 电源 (不要从 USB-TTL 取电, 屏需要 5V/500mA+)

步骤:
  ① 连接好硬件
  ② USART HMI 软件 → 工具栏 → 下载
  ③ 选择 USB-TTL 对应的 COM 口
  ④ 波特率默认 115200
  ⑤ 点击"下载" → 等待进度条走完
```

#### 方式 B：SD 卡下载（批量/现场）

```
步骤:
  ① 编译生成的 .tft 文件复制到 microSD 卡根目录
  ② SD 卡插入屏幕卡槽
  ③ 屏幕重新上电
  ④ 屏幕自动检测 SD 卡中的 .tft 文件并烧录
  ⑤ 烧录完成后拔掉 SD 卡
```

### 6.3 下载后验证

下载完成后屏幕会重启，应显示 Page 0 波形页。

用串口助手（115200, 8N1）发指令测试：
```
n0.val=150
```
→ 屏幕应显示 150。

发完后必须加 `FF FF FF`（3字节），串口助手需支持 HEX 发送。

## 7. 调试技巧

### 7.1 组件 objname 核对

编译前 → 菜单 → **视图** → **组件列表** → 检查所有 objname 是否与代码一致：

```
期望                   实际（在软件中核对）
─────────────────────────────────────────
s0                     □
n0, n1, n2             □ □ □
b0, b1, t4             □ □ □
s1                     □
t9~t17                 □ □ □ □ □ □ □ □ □
Page 1 b0              □
```

### 7.2 串口助手测试

MCU 没写好之前，用 PC 串口助手验证屏幕：

```
串口助手 → 115200, 8N1, HEX发送

测试1: 数字组件 (小数)
  发送 (HEX): 6E 30 2E 76 61 6C 3D 31 35 30 2E 32 FF FF FF
  即 ASCII: "n0.val=150.2" + FF FF FF
  预期: n0 显示 150.2

测试2: 波形
  发送 (HEX): 61 64 64 74 20 30 2C 35 2C 31 30 30 2C 35 30 2C 32 30 30 2C 31 35 30 2C 31 30 30 2C FF FF FF
  即 ASCII: "addt 0,5,100,50,200,150,100," + FF FF FF
  预期: s0 上画 5 个点

测试3: 页面切换
  发送 (HEX): 70 61 67 65 20 31 FF FF FF
  即 ASCII: "page 1" + FF FF FF
  预期: 切换到 Page 1
```

### 7.3 printh 触摸返回验证

按屏幕按钮时，串口助手应收到：

```
b0 (Page 0) 按下: 55 00 00 01 FF FF FF    ← printh 55 00 00 01
b1 (Page 0) 按下: 55 00 01 01 FF FF FF    ← printh 55 00 01 01
b0 (Page 1) 按下: 55 01 00 01 FF FF FF    ← printh 55 01 00 01
```

### 7.4 常见问题

| 症状 | 可能原因 | 排查 |
|------|---------|------|
| 屏幕不亮 | 5V 供电不足 | 测电源电流，屏幕需 500mA+ |
| 通信无响应 | TX/RX 接反 | 交叉验证：屏TX↔MCU RX, 屏RX↔MCU TX |
| 波形不刷新 | USART2 中断未开 | 检查 CubeMX NVIC 设置 |
| 按钮无触摸返回 | printh 脚本未写或帧格式错 | 检查按钮按下事件脚本 |
| 数字显示异常 | 组件 objname 不匹配 | 核对 objname，拖入后需手动改掉自动编号 |
| 编译报错 | 字体文件缺失 | 菜单 → 工具 → 字体管理 → 添加中文字体 |
| 下载失败 | COM 口被占用 | 关闭其他串口工具，检查设备管理器 |
